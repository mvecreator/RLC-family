# Scenario Lab — последовательная проверка поведения модели

Цель лаборатории — не подгонять модель под один красивый пример, а постоянно сочинять разные бытовые ситуации и проверять, сохраняет ли вычислительная схема разумное направление эффектов.

Запуск:

```bash
python3 simulator/scenario_lab.py
```

Лаборатория строит сценарии через тот же `SIM-TIME1`, которым пользуется чат.

## Первый набор ситуаций

### 1. Спокойная семья

Низкое напряжение, хороший канал общения, хороший внешний сброс, нормальный финансовый резерв.

Наблюдение первого прогона:

```text
memory: 0.120 -> ~0.070 за 14 дней
```

То есть без новых возмущений накопленное состояние релаксирует.

### 2. Хроническое напряжение

Высокое внутреннее напряжение, слабый канал, сильное эмоциональное усиление, заметный внешний фон, слабый сброс.

Наблюдение:

```text
memory -> 1.000
```

Модель входит в насыщенный режим памяти.

### 3. Одинаковая ссора: молчание против разговора

Общий старт одинаковый.

Вариант A:

```text
ссора
→ два дня слабого канала общения
```

Вариант B:

```text
ссора
→ быстрый разговор
→ хороший канал
→ согласованный внешний сброс
```

После исправления динамики памяти:

```text
final memory, silence ≈ 0.311
final memory, talk    ≈ 0.285
```

То есть разговор больше не получает математический штраф за то, что хороший проводник уменьшает электрическое сопротивление.

## Найденный дефект №1

Первая версия SIM-TIME1 использовала последовательное `R_CHANNEL` одновременно как:

1. физическое сопротивление канала;
2. косвенный показатель качества коммуникации.

Это приводило к неприятному артефакту:

> плохой канал повышал R, а высокое R сильнее демпфировало RLC-контур, поэтому молчание могло выглядеть полезным.

Исправление:

память теперь получает отдельный вклад

```text
channel_stress ∝ (1 - communication_quality) * tension
```

и отдельную релаксацию от работающего канала.

То есть физический ток и качество общения больше не считаются одним и тем же явлением.

### 4. Сильный внешний сигнал: слабый и сильный фильтр

При одинаковом внешнем возбуждении:

```text
peak current, weak filter   ≈ 0.117
peak current, strong filter ≈ 0.016
```

Фильтрация внешнего поля работает в ожидаемом направлении.

### 5. Подростковая нелинейность при высоком напряжении

Первая версия почти не различала такие сценарии, потому что рост сопротивления уменьшал ток и тем самым мог выглядеть стабилизирующим.

После исправления:

```text
final memory without nonlinear stress ≈ 0.512
final memory with nonlinear stress    ≈ 0.546
```

## Найденный дефект №2

Нелинейность ребёнка раньше влияла в основном через увеличение `R_CHILD`.

Это недостаточно: большое сопротивление в RLC-смысле может одновременно увеличить демпфирование.

Исправление:

при высоком напряжении введён отдельный вклад

```text
nonlinear_stress
  ∝ adolescent_nonlinearity
  * max(tension - threshold, 0)
```

в динамику памяти.

### 6. Финансовый перегруз

Пример:

```text
income       = 3600 / month
mortgage     = 1600
base load    = 2200
other load   = 700
reserve      = 5000
window       = 120 days
```

Первый прогон:

```text
reserve: 5000 -> ~1452
```

Модель правильно показывает медленное исчерпание буфера.

## Отдельная оговорка по зарплате

В текущем SIM-TIME1 поле

```text
доходы_в_месяц
```

представляет **средний непрерывный денежный поток**.

Поэтому событие `денежный_импульс` должно означать разовую сумму, **не включённую** в этот средний поток: премию, подарок, возврат, продажу и т. п.

Иначе зарплата будет посчитана дважды.

Поэтому демонстрационный timeline изменён с «пришла зарплата» на «пришла разовая премия».

Будущий `SIM-CASHFLOW1` может ввести настоящий кассовый режим, где зарплата, ипотека и счета приходят отдельными дискретными событиями.

## Автоматические sanity checks

`scenario_lab.py` сейчас проверяет:

```text
calm_memory_decays
chronic_memory_exceeds_calm
talk_beats_silence_on_final_memory
filter_reduces_external_peak
nonlinearity_increases_memory_under_tension
financial_overload_consumes_reserve
```

Это не доказательство реалистичности модели.

Это минимальный регрессионный контракт:

> после изменения формул модель не должна внезапно начать вознаграждать явно противоположное тому, что сама теория считает стабилизирующим действием.

## Метод дальнейшей работы

Теперь развитие должно идти циклом:

```text
1. придумать бытовую ситуацию
2. сформулировать ожидаемое качественное направление
3. прогнать solver
4. посмотреть траекторию
5. найти странности
6. исправить модель, а не текст интерпретации
7. добавить найденный эффект в regression suite
8. перейти к следующей ситуации
```

Главное правило:

> **Если результат выглядит нелепо, сначала подозреваем уравнения, а не семью.**

## Найденный дефект №3 — финансовая подсистема была односторонней

RLC-FAMILY-6 уже утверждала `COUPLING1`: финансовый дефицит способен менять параметры семейной динамики.

Но первая версия SIM-TIME1 только считала резерв и долг параллельно. При одинаковых отношениях:

```text
здоровые финансы
и
почти исчерпанный резерв + дефицит
```

давали одинаковые ток и память.

Это означало, что код не реализовывал собственную теорию.

### Исправление

Введён bounded-параметр:

```text
financial_stress =
    0.70 * deficit_ratio
  + 0.30 * short_runway_stress
```

с ограничением `[0,1]`.

Он влияет на:

1. эффективное возбуждение контура;
2. скорость накопления памяти.

Это внутренний коэффициент RLC-family, а не психологическая шкала.

Сравнительный 30-дневный прогон при одинаковых отношениях:

```text
здоровые финансы:
  final memory ≈ 0.238
  peak financial stress = 0

дефицит + короткий резерв:
  final memory ≈ 0.827
  peak financial stress ≈ 0.497
```

Теперь финансовая шина действительно связана с RLCM-ядром.

## 7. Поддерживающий и подзуживающий внешний канал

После одинаковой ссоры сравниваются:

### A. Согласованный сброс

Хороший внешний собеседник:

- высокий matching;
- высокий dump;
- нормальный канал.

### B. Подзуживающий канал

Внешний разговор:

- усиливает фон;
- усиливает антенну;
- увеличивает эмоциональное усиление;
- почти не фильтруется.

Первый прогон:

```text
helpful support:
  peak current ≈ 0.086
  final memory ≈ 0.393

stoking support:
  peak current ≈ 0.190
  final memory ≈ 0.413
```

То есть одна и та же «антенна наружу» может работать либо как демпфер, либо как дополнительный источник возбуждения.

## 8. Оптофинансовый свет при дефиците

Одинаковая семья находится в финансово напряжённом режиме.

Сравниваются:

```text
weak money light / poor coupling
vs
strong money light / good coupling
```

Первый прогон:

```text
weakly illuminated:
  final reserve ≈ 1830
  final memory ≈ 0.676

well illuminated:
  final reserve ≈ 2836
  final memory ≈ 0.521
```

То есть PHOTO/LASER-ветка теперь влияет не только на красивую финансовую метафору: дополнительный денежный поток уменьшает финансовый стресс, а тот уже меняет динамику памяти.

## Текущий sanity-набор

Теперь лаборатория проверяет дополнительно:

```text
financial_stress_couples_into_family_memory
helpful_support_beats_stoking_support
money_light_reduces_financially_coupled_memory
```

Таким образом первый цикл сценарных испытаний уже не просто подтвердил модель, а обнаружил три архитектурных дефекта и заставил изменить уравнения.
