# PERSON-CAL — калибровка смешанной модели персонажей

PERSON-CAL проверяет, что PERSON2 не превращается в жёсткий гендерный шаблон и сохраняет уже работающую legacy-модель.

## Текущие gates

| Gate | Проверка | Результат текущих коэффициентов |
|---|---|---|
| PCAL01 | мужчина: neutral -> сильный caregiving | `C 1.646 -> 1.087`, `L 1.354 -> 1.913` |
| PCAL02 | женщина: neutral -> provider/directive | `C 1.354 -> 1.866`, `L 1.646 -> 1.134` |
| PCAL03 | `gender_prior_strength=0` | одинаковые роли дают одинаковые R/L/C |
| PCAL04 | роль переворачивает weak prior | муж может получить `L>C`, жена `C>L` |
| PCAL05 | `R_child(age)` | `2.265 > 1.458 > 0.785 > 0.399` для 3/8/13/17 лет |
| PCAL06 | legacy boy | `C/L` растёт `1.127 -> 1.378 -> 1.696 -> 2.020` |
| PCAL07 | legacy girl | `L/C` растёт тем же возрастным рядом |
| PCAL08 | temperament override | сильный individual bias переворачивает child legacy prior |
| PCAL09 | positivity | экстремальные профили сохраняют `R>0, C>0, L>0` |
| PCAL10 | legacy preservation | CALIB1 остаётся `12/12` |

## Важный смысл

`gender` в PERSON2 — не измеряемая физическая причина параметров. Он используется только как опциональный legacy-prior исходной сатирической теории.

Главная иерархия:

```text
фактическая роль
+ индивидуальный temperament
+ слабый optional legacy gender prior
-> effective orientation
-> C_p / L_p
```

При `gender_prior_strength=0` одинаковые роли и temperament дают одинаковые RLC-параметры независимо от gender label.

## Детская возрастная гипотеза

Возрастное падение `R_child` и boy/girl C/L-профили относятся только к внутренней сатирической модели. Они не являются эмпирическими утверждениями о развитии детей.

Гендерная возрастная ветка вообще включается только через:

```text
legacy_gender_profile = true
```

Без неё возраст влияет на `R_child`, а реактивный профиль определяется индивидуальными параметрами.

## Следующий gate

После PERSON-CAL используется PERSON-NET1: каждый персонаж остаётся отдельным узлом, а не сворачивается обратно в один общий RLC.

Это позволяет проверять уже сетевые вопросы:

- кто имеет максимальную амплитуду;
- какой канал несёт максимальный ток связи;
- насколько расходятся фазы персонажей;
- как качество конкретной связи меняет выравнивание узлов.
