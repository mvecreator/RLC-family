# PERSON-TIME-CAL — калибровка адресной динамики

PERSON-TIME-CAL проверяет не содержание семейных советов, а базовую корректность распространения сигнала по PERSON2-сети.

## Gates

| Gate | Проверка |
|---|---|
| PTCAL01 | без событий PERSON-TIME2 остаётся в стартовом равновесии без ложного voltage transient |
| PTCAL02 | адресный импульс даёт максимальный peak на target_person |
| PTCAL03 | более качественный канал передаёт больший отклик второму узлу |
| PTCAL04 | memory impulse в t=0 меняет только target_person |
| PTCAL05 | временное изменение качества действует только на target_link и после события откатывается |
| PTCAL06 | при нулевом financial_stress премия меняет reserve, но не person memory |
| PTCAL07 | финансовый stress действует как общий фон на все узлы |
| PTCAL08 | повторный запуск детерминирован |

## Редуцированная двухузловая проверка уравнений

Для одинаковых PERSON2-узлов и локального импульса на A:

```text
peak |v_A| ≈ 0.082
peak |v_B| ≈ 0.018
```

То есть прямое возбуждение остаётся локальным, но передаётся по связи.

При изменении качества единственного канала:

```text
quality 0.20:
  receiver peak ≈ 0.010

quality 0.90:
  receiver peak ≈ 0.027
```

Это подтверждает направленный принцип:

> хороший канал сильнее передаёт взаимодействие.

Большой ток/отклик сам по себе не считается конфликтом.

## Финансовый контроль

При достаточном резерве и нулевом financial_stress:

```text
bonus +1000
-> reserve +1000
-> person memory delta = 0
```

При дефиците и малом резерве financial_stress действует как общий фон и повышает индивидуальную memory dynamics для всех узлов.

## Запуск

```bash
python3 simulator/person_time_calibration.py
python3 -m unittest tests.test_person_time_calibration -v
```

## Адресация

Персонаж:

```json
{"персонаж":"wife"}
```

Связь:

```json
{"связь":["husband","son"]}
```

или строкой только в однозначной форме:

```text
husband->son
husband:son
```

Форма `husband-son` не используется, потому что дефис допустим внутри самого ID.

## Назначение

PERSON-TIME-CAL должен оставаться обязательным gate перед изменением:

- динамических уравнений узлов;
- coupling между людьми;
- event compiler;
- financial coupling;
- индивидуальной memory model.

Следующий уровень калибровки — PERSON-COMPARE-CAL: сравнение двух альтернативных действий после одного и того же исходного события.
